# Repository guide

## Language and conventions

- Use English for project communication, documentation, and code comments. Keep translations in their target languages and preserve domain names and identifiers.
- Follow the existing TypeScript and React conventions. Fix type errors without weakening strict checks or hiding errors with broad assertions.
- Keep changes within the requested scope and preserve unrelated work and user data.

## Code map

- `packages/ship-info/src/index-src.ts`: poi plugin entry and lifecycle exports.
- `packages/ship-info/src/views/`: main interface, table, sidebar, state, lifecycle, persistence, and table utilities.
- `packages/navy-staff/src/`: standalone planner entry, lifecycle, migration, state, selectors, and screenshot capture.
- `packages/shared/src/`: classification, host fleet selectors, shared UI, serialized writes, and persistence lifecycle; bundled into consumers.
- `packages/*/i18n/`: self-contained packaged translations. Shared UI (fleet icons and controls) ships as inline React components from `packages/shared/src/ui/`, not binary assets.
- `shims/`: local dependency and poi type declarations.
- `build/plugin.config.ts`: shared plugin build settings (`vp pack`) and poi-provided external dependencies; `packages/*/vite.config.ts` re-export it.
- `vite.config.ts`: repository tests, lint, and format configuration.
- `scripts/release/`: native pnpm release preparation, changelog enforcement, Release PR validation, packing, and publishing.
- `.github/workflows/`: CI plus Prepare release, Release PR validation, and Publish release.
- `.changeset/`: pnpm change intents and the generated ledger.
- `docs/releases.md`: release workflow and external setup.

## Release conventions

- Use the pinned pnpm version's native release tooling (`pnpm change`, `pnpm version -r`). Do not add or run the Changesets CLI.
- Never bump plugin versions, edit released changelog sections, or edit `.changeset/ledger.yaml` by hand.
- Every PR that changes plugin runtime, package, shared, or runtime-affecting build/dependency paths needs new `.changeset` intents. Shared/build changes need coverage for both plugins. Use `none` only with an explanation. Pure tests and docs are exempt. Never reuse an intent filename that exists in base history; pnpm ignores consumed ids.
- Write non-empty intent summaries in English; keep localized names and proper nouns unchanged.
- Ordinary PR merges must never publish. Releases go through Prepare release (workflow_dispatch), the generated Release PR, and Publish release after merge. Prepare release requires the configured GitHub App secrets.
- Do not hand-edit a Release PR, plan, or generated files. A stale plan (base advanced) must be regenerated by rerunning Prepare release.
- Publish only plan-selected, verified tarballs. An existing exact version is skipped only when the registry integrity matches the verified tarball. Tags are `poi-plugin-ship-info@VERSION` and `poi-plugin-navy-staff@VERSION`; never move or delete old `v*` tags, and never move `latest` backwards.
- Treat registry errors as failures. A failed publication must be retryable without republishing an existing version or overwriting its tags.
- Root and `@poi-plugins/shared` are private and never published.

## Development

Use pnpm directly, with the version pinned in `package.json`:

```sh
pnpm install --frozen-lockfile
pnpm run check
pnpm test
pnpm run build
pnpm run pack
pnpm run verify:package
git diff --check
```

- Run type checks, builds, and relevant behavior checks for runtime changes. For documentation changes, check content, links, and whitespace.
- `pnpm run check` runs `tsc --noEmit`. `pnpm test` runs the Vitest suite in `tests/` (`vp test run`). `pnpm run lint` and `pnpm run fmt` are the optional Vite+ lint/format tools; formatting is not a required gate.
- Preserve the build's host dependency conventions. Verify packaged entry points, translations, and inline UI assets when changing packaging.
