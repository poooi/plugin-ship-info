# Change intents

This directory uses the [changesets file format](https://github.com/changesets/changesets)
with pnpm's native release tooling. Do **not** install or run the Changesets CLI:
`pnpm change` writes these files and `pnpm version -r` consumes them, records the
ledger, and writes the per-package `CHANGELOG.md`.

## Adding an intent

```sh
pnpm change --bump patch --summary "Fix the table filter reset" poi-plugin-ship-info
```

A file in this directory then looks like:

```markdown
---
"poi-plugin-ship-info": patch
---

Fix the table filter reset.
```

You can also write the file by hand with a new, descriptive filename.

- Use `patch`, `minor`, `major`, or `none`.
- `none` is an explicit decline. It is allowed only with a non-empty summary
  explaining why the change does not need a release.
- pnpm applies the largest bump requested for a package in the release: `major`
  wins over `minor`, and `minor` wins over `patch`. A `none` entry declines a
  release only when no other intent requests a real bump for that package.
- The summary must be non-empty, and English is required by convention. There is
  no automatic language detection, so keep non-ASCII proper nouns (ship names,
  localized labels, and similar names) as they are; do not transliterate them
  just to satisfy an ASCII check.
- Name only publishable plugin packages: `poi-plugin-ship-info` and
  `poi-plugin-navy-staff`. The root workspace and
  `@poi-plugins/shared` are private, are excluded from versioning, and
  must not be named in an intent.
- Changes under `packages/shared/` or build/dependency configuration affect both
  plugins. Add coverage for both packages, either in one intent or in two new
  intents.
- Pure test and documentation changes do not need an intent.

## Pull request rules

- Add a **new** intent file. Editing, renaming, or deleting an existing intent
  does not count toward coverage and is rejected on ordinary pull requests.
- Do not reuse an intent filename that already exists in repository history
  reachable from the base. pnpm ignores an id it has already consumed, so the
  check rejects a re-added or recreated filename. Intent filenames are never
  reused.
- Do not edit plugin versions by hand. The only exception is the documented
  initial Navy baseline normalization on the setup pull request.
- The changelog CI compares the pull request base and head. Only new intent
  files count, so an old intent cannot be reused or edited to bypass the check.
- Malformed frontmatter, empty summaries, unknown packages, and unknown bump
  types are rejected.
- The generated `.changeset/ledger.yaml` belongs to `pnpm version -r`; do not
  edit it by hand.
- Release PRs are generated by the Prepare release workflow. Do not hand-edit
  them or their release notes.

See [docs/releases.md](../docs/releases.md) for the full release process.
